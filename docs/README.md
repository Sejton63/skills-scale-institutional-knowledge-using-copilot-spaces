# OctoAcme Project Management Docs

This repository contains the core project management guidance used by OctoAcme. It is intended to be the entry point for team members, stakeholders, and delivery partners who need a quick understanding of how projects are initiated, planned, executed, released, and improved over time.

## Project management process summary

OctoAcme follows a lightweight, iterative project lifecycle designed to balance speed, accountability, and quality:

1. Initiation — confirm the business problem, define success measures, identify stakeholders, and decide whether to proceed.
2. Planning — align on scope, milestones, dependencies, backlog priorities, and delivery responsibilities.
3. Execution — build in small increments, track progress, triage blockers, validate quality, and keep communication flowing.
4. Release — verify readiness, deploy with controls, communicate outcomes, and support rollback if needed.
5. Retrospective — capture lessons learned, document action items, and feed improvements back into the next cycle.

Across the lifecycle, OctoAcme emphasizes customer value, clear ownership, measurable outcomes, iterative delivery, and regular communication across project roles.

## Core roles and responsibilities

- Project Manager (PM): coordinates planning, schedules, risk management, and stakeholder communication.
- Product Lead / Product Manager: defines outcomes, priorities, and success metrics.
- Developers: design, implement, test, and deliver product and platform changes.
- QA / Testing: validate acceptance criteria, quality gates, and release readiness.
- Stakeholders: provide inputs, alignment, approvals, and business context.

## Key project artifacts

- Project charter / one-pager
- Roadmap and release plan
- Backlog with acceptance criteria
- Risk register and dependency tracker
- Definition of Done
- Release notes and deployment checklist
- Retrospective action items and follow-up tracking
